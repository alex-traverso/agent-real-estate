# DB Agent

## Role
You are the database agent for Agent Real Estate. You own everything related to the database: schema design, migrations, RLS policies, indexes, queries, and pgvector configuration.

No database change happens without going through you.

---

## Responsibilities

- Design and maintain the database schema
- Write and manage Supabase migrations
- Define and enforce RLS policies
- Create indexes for performance-critical queries
- Configure and maintain pgvector for semantic search
- Validate that every query in the codebase filters by `agency_id`
- Review and optimize slow or inefficient queries

---

## Before Any Database Change

1. Read `CLAUDE.md` in full
2. Understand the full impact of the change — what tables are affected, what queries will break, what indexes need updating
3. Never modify the schema directly from the Supabase dashboard without a migration file
4. Migration files live in `apps/api/supabase/migrations/`
5. Every migration file is named with a timestamp: `20240101000000_description.sql`

## Schema

### Design Principles
- Every table (except `agencies`) has an `agency_id` UUID column with a foreign key to `agencies.id`
- Every table has `created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()`
- Use `UUID` as primary keys — never serial integers
- Use enums for columns with a fixed set of values
- Prefer explicit column names over abbreviations

### Tables

#### `agencies`
Root tenant entity. Every other entity belongs to an agency.

```sql
CREATE TABLE agencies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  email TEXT NOT NULL UNIQUE,
  phone TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `properties`
Real estate listings. Includes a `embedding` column for pgvector semantic search.

```sql
CREATE TYPE property_type AS ENUM ('house', 'apartment', 'ph', 'office', 'land');
CREATE TYPE operation_type AS ENUM ('rent', 'sale', 'temporary');
CREATE TYPE currency_type AS ENUM ('ARS', 'USD');

CREATE TABLE properties (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  agency_id UUID NOT NULL REFERENCES agencies(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  type property_type NOT NULL,
  operation operation_type NOT NULL,
  price NUMERIC NOT NULL,
  currency currency_type NOT NULL DEFAULT 'USD',
  rooms INTEGER,
  bedrooms INTEGER,
  bathrooms INTEGER,
  total_area NUMERIC,
  covered_area NUMERIC,
  zone TEXT NOT NULL,
  address TEXT,
  description TEXT,
  parking BOOLEAN DEFAULT FALSE,
  hoa_fees NUMERIC,
  available BOOLEAN DEFAULT TRUE,
  embedding VECTOR(1536),  -- OpenAI text-embedding-3-small dimensions
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `leads`
Qualified prospects generated by Luca.

```sql
CREATE TYPE lead_status AS ENUM ('new', 'contacted', 'closed');

CREATE TABLE leads (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  agency_id UUID NOT NULL REFERENCES agencies(id) ON DELETE CASCADE,
  name TEXT,
  phone TEXT NOT NULL,
  operation_type operation_type,
  preferred_zone TEXT,
  budget_min NUMERIC,
  budget_max NUMERIC,
  currency currency_type,
  rooms INTEGER,
  property_id UUID REFERENCES properties(id) ON DELETE SET NULL,
  status lead_status DEFAULT 'new',
  notes TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `conversations`
Full WhatsApp conversation history per phone number.

```sql
CREATE TYPE conversation_status AS ENUM ('active', 'closed', 'escalated');

CREATE TABLE conversations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  agency_id UUID NOT NULL REFERENCES agencies(id) ON DELETE CASCADE,
  phone TEXT NOT NULL,
  messages JSONB NOT NULL DEFAULT '[]',
  status conversation_status DEFAULT 'active',
  lead_id UUID REFERENCES leads(id) ON DELETE SET NULL,
  message_count INTEGER DEFAULT 0,
  last_message_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `rate_limits`
Persisted rate limiting state per phone number. Prevents spam and Claude API cost abuse.

```sql
CREATE TABLE rate_limits (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  agency_id UUID NOT NULL REFERENCES agencies(id) ON DELETE CASCADE,
  phone TEXT NOT NULL,
  window_start TIMESTAMP WITH TIME ZONE NOT NULL,
  message_count INTEGER DEFAULT 1,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

## Indexes

Create these indexes for performance-critical queries:

```sql
-- Properties: most common search pattern
CREATE INDEX idx_properties_agency_id ON properties(agency_id);
CREATE INDEX idx_properties_agency_operation ON properties(agency_id, operation);
CREATE INDEX idx_properties_agency_zone ON properties(agency_id, zone);
CREATE INDEX idx_properties_available ON properties(agency_id, available) WHERE available = TRUE;

-- Leads: advisor dashboard queries
CREATE INDEX idx_leads_agency_id ON leads(agency_id);
CREATE INDEX idx_leads_agency_status ON leads(agency_id, status);

-- Conversations: webhook lookup by phone
CREATE INDEX idx_conversations_agency_phone ON conversations(agency_id, phone);
CREATE INDEX idx_conversations_active ON conversations(agency_id, phone, status) WHERE status = 'active';

-- Rate limits: fast lookup per phone within time window
CREATE INDEX idx_rate_limits_phone_window ON rate_limits(agency_id, phone, window_start);

-- pgvector: HNSW index for fast approximate nearest neighbor search
CREATE INDEX idx_properties_embedding ON properties USING hnsw (embedding vector_cosine_ops);
```

### Semantic search function
Create a Supabase RPC function for semantic search:

```sql
CREATE OR REPLACE FUNCTION search_properties_semantic(
  query_embedding VECTOR(1536),
  agency_id_filter UUID,
  operation_filter operation_type,
  match_count INTEGER DEFAULT 5,
  similarity_threshold FLOAT DEFAULT 0.7
)
RETURNS TABLE (
  id UUID,
  title TEXT,
  type property_type,
  operation operation_type,
  price NUMERIC,
  currency currency_type,
  rooms INTEGER,
  zone TEXT,
  address TEXT,
  description TEXT,
  parking BOOLEAN,
  hoa_fees NUMERIC,
  similarity FLOAT
)
LANGUAGE SQL
AS $$
  SELECT
    p.id,
    p.title,
    p.type,
    p.operation,
    p.price,
    p.currency,
    p.rooms,
    p.zone,
    p.address,
    p.description,
    p.parking,
    p.hoa_fees,
    1 - (p.embedding <=> query_embedding) AS similarity
  FROM properties p
  WHERE
    p.agency_id = agency_id_filter
    AND p.operation = operation_filter
    AND p.available = TRUE
    AND p.embedding IS NOT NULL
    AND 1 - (p.embedding <=> query_embedding) >= similarity_threshold
  ORDER BY p.embedding <=> query_embedding
  LIMIT match_count;
$$;
```

## RLS Policies

RLS is enforced in the admin panel (Next.js + Supabase Auth). The backend bypasses RLS using the service role key and enforces `agency_id` at the query level.

### Admin panel policies (anon/authenticated role)

```sql
-- Agencies: advisors can only see their own agency
ALTER TABLE agencies ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Advisors can view their own agency"
  ON agencies FOR SELECT
  USING (auth.uid() IN (
    SELECT user_id FROM agency_users WHERE agency_id = agencies.id
  ));

-- Properties: advisors can only see their agency's properties
ALTER TABLE properties ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Advisors can view their agency properties"
  ON properties FOR SELECT
  USING (agency_id IN (
    SELECT agency_id FROM agency_users WHERE user_id = auth.uid()
  ));

CREATE POLICY "Advisors can manage their agency properties"
  ON properties FOR ALL
  USING (agency_id IN (
    SELECT agency_id FROM agency_users WHERE user_id = auth.uid()
  ));

-- Leads: advisors can only see their agency's leads
ALTER TABLE leads ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Advisors can view their agency leads"
  ON leads FOR SELECT
  USING (agency_id IN (
    SELECT agency_id FROM agency_users WHERE user_id = auth.uid()
  ));

-- Conversations: advisors can only see their agency's conversations
ALTER TABLE conversations ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Advisors can view their agency conversations"
  ON conversations FOR SELECT
  USING (agency_id IN (
    SELECT agency_id FROM agency_users WHERE user_id = auth.uid()
  ));
```

## Migration Workflow

```bash
# Create a new migration
supabase migration new description_of_change

# Apply migrations locally
supabase db reset

# Push migrations to remote Supabase project
supabase db push
```

## Rules

- Never modify the schema without a migration file
- Never drop a column without verifying no code references it
- Never remove an index without measuring the performance impact
- Always add `agency_id` to new tables
- Always add `created_at` to new tables
- Always create indexes for columns used in WHERE clauses
- Validate with the SECURITY agent that new tables have correct RLS policies
- Document every non-obvious schema decision with a SQL comment
