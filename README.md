# Agent Real Estate 🏠

A WhatsApp AI agent for real estate agencies that qualifies leads 24/7 through natural conversation, filters properties based on client criteria using semantic search, and delivers ready-to-close leads to advisors.

---

## The Problem

Small real estate agencies and independent agents lose leads daily because:

- They can't respond to inquiries outside business hours
- Manually qualifying a lead (understanding what the client is looking for) consumes valuable advisor time
- There's no structured record of what each prospect was looking for

**The result:** a client who reaches out at 10pm and gets no response until the next morning has already contacted another agency.

## The Solution

An AI agent named **Luca** that:

- Responds instantly to WhatsApp messages at any hour
- Qualifies prospects through natural, friendly conversation
- Searches for matching properties using both structured filters and semantic similarity
- Generates a complete lead profile and notifies the advisor when a client is ready to move forward

**The advisor arrives in the morning with qualified leads waiting — not unanswered messages.**

## Getting Started

### Prerequisites

- **Node.js 22+** (`.nvmrc` pins the version) and **Yarn 4** (via Corepack — `corepack enable`)
- **Docker Desktop** — required to run the local Supabase stack
- **Supabase CLI** — used as `npx supabase …` from `apps/api/` (no global install needed)
- **Hookdeck CLI** — delivers Meta webhooks to your local server ([install](https://hookdeck.com/docs/cli))
- **Anthropic API key** (the agent) and **OpenAI API key** (embeddings)
- **Meta Cloud API credentials** (WhatsApp Business) and a **Resend account** (email notifications)

> A cloud Supabase account is optional — you can develop entirely against the local Docker stack.

### 1. Install & environment

```bash
# Clone and install
git clone https://github.com/alextraverso/agent-real-estate.git
cd agent-real-estate
yarn install

# packages/types is a real compiled package (apps/api requires it at runtime,
# not just for typechecking) — build it before starting the backend, and
# again any time database.types.ts is regenerated.
yarn workspace types build

# Create the env files (there are two — one per app)
cp .env.example apps/api/.env         # backend (NestJS)
cp .env.example apps/admin/.env.local # admin panel (Next.js)
```

Fill in the values as you go (see [Environment Variables](#environment-variables)). The backend
reads `apps/api/.env`; the admin panel reads `apps/admin/.env.local`.

### 2. Database

Migrations live in `apps/api/supabase/migrations/`. Pick one of the two setups. All Supabase CLI
commands run from `apps/api/` (that's where `supabase/config.toml` lives).

**Option A — Local stack (Docker, recommended for development)**

```bash
cd apps/api

# Start the local Supabase stack (Postgres + Studio + Auth + Mailpit) in Docker.
# On first run it prints the local API URL and the anon / service_role keys.
npx supabase start

# Apply all migrations (and the SQL seed, if present) to the local database.
npx supabase db reset
```

Copy the printed values into your env files:
`SUPABASE_URL=http://127.0.0.1:54321`, plus the `service_role` key (backend) and `anon` key
(admin). Useful local URLs: **Studio** → `http://127.0.0.1:54323`, **Mailpit** (captured emails)
→ `http://127.0.0.1:54324`.

**Option B — Cloud project**

```bash
cd apps/api

npx supabase link --project-ref <your-project-ref>
npx supabase db push   # applies local migrations to the remote database
```

Set `SUPABASE_URL` and the keys from your project's dashboard (Settings → API).

### 3. Seed demo data + embeddings

The property embeddings are generated by a TypeScript seed (not the SQL seed), so run it against
whichever database you configured above. It needs `OPENAI_API_KEY` set in `apps/api/.env`.

```bash
# Seeds the demo agency, sample properties, and their vector embeddings
yarn workspace api seed

# Optional: verify semantic search returns ranked results for a sample query
yarn workspace api search:smoke
```

### 4. Run the apps

```bash
# Backend (NestJS) — http://localhost:3000
yarn workspace api start:dev

# Admin panel (Next.js)
yarn workspace admin dev
```

> ⚠️ **Port collision:** both the API and the Next.js admin default to port `3000`. Run one on a
> different port — e.g. start the API with `PORT=3001 yarn workspace api start:dev`, or the admin
> with `yarn workspace admin dev -p 3001`. Keep whichever port the webhook targets (below) in sync.

### 5. Receive WhatsApp webhooks locally (Hookdeck)

Meta needs a public URL to deliver webhooks. Hookdeck exposes one and relays each event to your
local server:

```bash
hookdeck login
hookdeck listen 3000 meta-whatsapp --path /webhook
```

This forwards events from a public Hookdeck source URL to `http://localhost:3000/webhook`. In the
Meta WhatsApp webhook configuration, set the **Hookdeck source URL** as the callback URL and
`META_VERIFY_TOKEN` as the verify token. The API exposes `GET /webhook` (verification) and
`POST /webhook` (inbound messages). Hookdeck forwards the raw request body untouched, so the
`X-Hub-Signature-256` signature (validated with `META_APP_SECRET`) stays valid.

### 6. Tests

```bash
yarn workspace api test
```

## Environment Variables

`.env.example` is the source of truth for the full list. Copy it into **two** files —
`apps/api/.env` (backend) and `apps/admin/.env.local` (admin panel) — and fill in real values.

```bash
# Supabase (backend uses the service_role key; admin uses the anon key)
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
SUPABASE_ANON_KEY=
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
DATABASE_URL=

# Anthropic (the agent)
ANTHROPIC_API_KEY=

# OpenAI (embeddings only)
OPENAI_API_KEY=
OPENAI_EMBEDDING_MODEL=          # defaults to text-embedding-3-small

# Meta Cloud API
META_APP_SECRET=                 # webhook X-Hub-Signature-256 validation
META_VERIFY_TOKEN=               # webhook verification (GET /webhook)
META_API_TOKEN=                  # outbound sender
META_PHONE_NUMBER_ID=            # outbound sender + demo agency link (seed)

# Resend
RESEND_API_KEY=
```

> ⚠️ **Never commit your `.env` files.** They are covered by `.gitignore`. Only `.env.example`
> (with no real values) should be committed.

## CI/CD

GitHub Actions runs on every push and pull request:

- **Typecheck** — `tsc --noEmit` on both apps
- **Lint** — ESLint on both apps
- **Build** — production build verification on both apps

Deployment is handled automatically:

- `main` → production (Railway + Vercel)
- `develop` → staging
- `feature/*` → CI only, no deployment

## Agent Capabilities

Luca, the WhatsApp AI agent, can:

| Capability                  | Description                                                                     |
| --------------------------- | ------------------------------------------------------------------------------- |
| Lead qualification          | Understands what the client is looking for through natural conversation         |
| Exact search                | Finds properties by specific address or reference                               |
| Filtered search             | Filters by zone, price, rooms, operation type, and more                         |
| Semantic search             | Understands vague descriptions ("something quiet with a garden") using pgvector |
| Lead generation             | Saves qualified leads with full context and notifies the advisor                |
| Escalation                  | Escalates to a human advisor when out of scope or on technical failure          |
| Prompt injection protection | Detects and neutralizes attempts to manipulate agent behavior                   |
| Rate limiting               | Prevents abuse per phone number                                                 |
| Session management          | Maintains conversation context with a 50-message limit                          |

## Security

- Meta webhook signature validation on every request
- Rate limiting per phone number
- Prompt injection detection in system prompt
- Multi-tenancy enforced at query level (`agency_id` on all tables)
- RLS policies on Supabase for additional data isolation
- Secrets managed via Railway and Vercel environment variables — never in code
